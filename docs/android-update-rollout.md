# Capital Fortune Android update rollout

## Current implementation

- The app opens on the manual launch gateway.
- Supabase's persisted login is read locally through the auth state listener; the game save is not requested until the player presses **Enter Fortune**.
- The launch button fetches `public/update-manifest.json` from the public repository with cache disabled.
- Optional updates allow the player to continue; a mandatory update blocks game entry.
- The official release page opens in an Android browser/custom tab. Android still asks the player to approve APK installation.

## Publishing a release

Update `public/update-manifest.json` in the same branch before publishing a release:

- `latestVersion`: new semantic version, e.g. `1.0.1`
- `minimumSupportedVersion`: oldest version allowed to connect
- `releaseUrl`: HTTPS GitHub release page containing the APK
- `releaseNotes`: short player-facing notes
- `mandatory`: true to require the update

The Android build currently generated by CI uses the default Capacitor/Gradle debug version (1.0.0). The release process must set a monotonically increasing Android `versionCode` and matching `versionName` and inject the same version into `VITE_APP_VERSION`. Do not publish a manifest version higher than the APK's actual version.

## Signing requirement — release blocker

Android only installs an APK as an in-place update when its signing certificate matches the installed app's certificate. The current CI workflow creates a fresh Android project and builds a debug APK on an ephemeral runner; it does not preserve a release signing key. Therefore:

1. A stable release keystore must be created and protected outside the repository.
2. Configure GitHub Actions secrets for the base64-encoded keystore, keystore password, key alias and key password.
3. Update the Android release workflow to sign every APK with that same key and increment versionCode.
4. Verify the signature of each release APK before publishing it.

The private key must never be committed to Git or embedded in the app. The original debug signing key used for earlier ephemeral CI APKs is not available in the repository. Consequently, the first transition from those APKs to a stable release signing key may require a one-time uninstall/reinstall and sign-in again. Cloud game progress remains on Supabase, but uninstalling clears the local remembered login.

## Installation boundary

This implementation does not silently install APKs. Android requires explicit user approval for sideloaded APK installation. Google Play distribution with Play In-App Updates is the smoother alternative if the app is later published through Play.
